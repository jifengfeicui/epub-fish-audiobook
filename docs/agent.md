# 项目 Agent

在项目页右下角打开 **Agent 助手**。使用设置中选中的 LLM 配置，模型需支持 Chat Completions 工具调用。浮窗可拖动、缩放或收起；Enter 发送，Shift+Enter 换行。收起不终止请求，定时任务不依赖网页打开。

使用 **新建对话** 开始独立上下文，**会话列表** 切换和查看记录，可重命名。首条消息自动作为默认标题；切换时保留各自尚未发送的草稿，刷新后恢复选中的会话。旧记录和待确认提案保存在“历史对话”，不会丢弃。模型仅回放同一会话、当前版本提示词下的最近记录，不回放历史私有推理，避免旧版“不支持B站/定时”的回答污染新请求。定时计划的运行记录在独立会话中显示；项目仍一次只运行一轮 Agent，不因新建对话绕过任务互斥。

## 操作能力与授权

Agent 可以使用当前项目的全部现有业务功能：

- 查询项目、章节原文、脚本、任务状态、日志和音频产物。
- 修改项目设置、归档、选择启用章节、重新识别章节、删除项目。
- 直接保存单章或整批脚本修改，保留修订历史与修改对照。
- 查询和更新角色资料、角色音色、项目旁白及项目音色排除列表。共享音色库只读。
- 提交预解析、TTS、整书合成、角色分析任务，暂停、继续、重试、取消任务。
- 查询 B 站登录及稿件状态、提取书籍元数据，提交视频准备、首发、追加、替换任务。
- 创建、查询、修改、暂停、恢复和删除当前项目的定时计划。

用户明确要求的操作直接执行，包括正文改写、覆盖式重新预解析和公开投稿，不再依赖改稿授权勾选框。没有要求改写的正文仍须保留。来源等必填信息缺失、目标不明确时应追问，不能编造。公开首发只有明确要求公开时才使用公开可见性；默认仍为仅自己可见。

每轮可以顺序执行多个相关操作。业务工具只接收明确类型的参数并复用已有校验；Agent 不执行任意代码或终端命令，不写全局配置，不操作其他项目。书籍文本与工具正文属于数据，不能当作授权指令。

章节号使用网页启用章节的连续编号；“当前章”指消息提交时的页面选中章节。预解析默认复用结果，只有明确要求重新生成才设置 `force_regenerate`。重新识别章节会清除现有脚本、角色、音频、产物及任务记录；已投稿的项目沿用原有禁止重新识别规则。删除项目是终止操作，删除成功后返回项目列表。

## 脚本与任务

先读脚本和版本再修改，单章和批量保存均检查版本；整批修改在同一事务中提交，失败整批回滚。批量工具支持一般脚本修改，以及精确删除指定的章节开头文本（支持跨条目，保留剩余正文、说话人和语气）。不能删成空章。

沿用现有脚本编辑条件：任务需暂停完成或已完成；请求暂停不等于暂停已完成。保存脚本使相应音频及整书产物过期，不自动执行配音。人工未保存的编辑会阻止聊天提交；后台脚本变化不覆盖网页未保存编辑。

历史待确认提案仍可确认或拒绝，不会因升级或权限变化自动应用。旧的 `agent_auto_apply_scripts` 和 `allow_text_rewrite` 字段保留兼容，但不再决定新请求的操作权限。

任务提交后显示编号和回执，实际完成情况以任务面板为准。操作记录、重复请求和重复工具调用均保留幂等处理；执行结果不确定或失败时不自动重放，也不能用另一种写工具绕过失败。

## 定时任务

向项目 Agent 描述要执行的任务和间隔，例如“每 10 分钟检查本书的 B 站状态，向当前稿件追加最多 10 个已经准备好的分 P”。这只是使用示例；升级不会创建任何计划。一本书仍对应一个稿件，每章作为一个分 P。

本项目的“每次上传 N 个稿件”按每批最多 N 个分 P 处理并在回执说明。未指定运行次数时持续至用户停用，无内容则跳过，不额外追问停止条件。账号、来源等实际执行条件缺失时准确说明并暂停。

Agent 保存的是每轮需要执行的任务正文，而非“创建计划”本身。到点调用同一项目 Agent，注入计划编号和定时来源，让它重新查询最新项目状态。定时运行不能递归创建新计划；遇到待执行任务应查询或跳过，不能重复提交。没有待处理内容可以正常跳过；停止条件由实际指令决定，达到时 Agent 可停用计划。

- 最短间隔为 60 秒；首轮默认等待一个间隔，也可指定包含时区的首次执行时间。
- 创建时保存选中的目标章节及原文指纹，章节失效或被替换后暂停，避免错误指向复用的章节编号。
- 一个项目同时只执行一轮 Agent 请求。忙时合并等待，不积压错过的轮次；重启后最多补一轮。
- 每轮失败、超时、中断、写操作失败或结果待核对时暂停；关联的业务任务晚于后续查询失败时，也会暂停并展示原因。
- 恢复是对已知故障的明确处置，重新等待一个间隔，保留最近运行结果；暂停或删除计划不取消已提交的业务任务。
- 计划及运行记录存 SQLite。关闭网页不影响调度，后端停止时不执行；归档项目不触发计划。

项目页的 **定时任务** 标签可查看说明、间隔、下次执行时间、最近结果和暂停原因，并暂停、恢复或删除。每轮唤醒会调用模型，可能产生模型费用。上传前仍需通过设置页面登录 B 站，Agent 只读取登录状态，不读取或展示凭据。

## API 与兼容

对话入口位于 `/api/v1/projects/{project_id}/agent`：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | 项目 Agent 基础路径 | 可传 `?conversation_id=UUID`；返回该会话最近 50 轮 `runs`、`conversation_id`、`conversations` 和 `project_busy` |
| GET | `/conversations` | 当前项目会话列表 |
| POST | `/conversations` | `{ title?: string }` 新建空白会话，返回 HTTP 201 |
| PATCH | `/conversations/{conversation_id}` | `{ title: string }` 重命名 |
| POST | `/messages` | 提交 `{ request_id: UUID, message, conversation_id?, selected_chapter_id? }`，返回 HTTP 202 |
| GET | `/runs/{run_id}` | 查询运行及全部操作 |
| POST | `/proposals/{proposal_id}` | 用 `{ approve: boolean }` 处理历史提案 |

运行响应包含有序 `actions[]`，每项具有 `id`、`position`、`kind`、`status`、`args`、`result`；旧 `action` 为首项或 `null`。定时运行包含 `automation_id`。消息重试必须沿用相同的 request_id 和消息参数。迁移保留旧记录及提案。

计划入口为 `/api/v1/projects/{project_id}/automations`：

| 方法 | 路径 | 请求或响应 |
|---|---|---|
| GET | 基础路径 | `{ automations: [...] }`，含最近运行摘要 |
| POST | 基础路径 | `{ instruction, interval_seconds, first_run_at?, selected_chapter_id? }`，返回 HTTP 201 |
| PATCH | `/{automation_id}` | `{ instruction?, interval_seconds?, enabled?, next_run_at? }` |
| DELETE | `/{automation_id}` | 删除，返回 HTTP 204 |

时间使用带时区的 ISO 8601，数据库统一存 UTC。模型使用最近 6 轮成功对话及全部操作状态；每轮预算仍为 8 次模型请求、12 次工具调用、120 秒。所有密钥及 B 站 cookie/token 从消息、工具结果、错误和持久记录中脱敏。业务操作先记录凭据再执行，进程中断后不自动重放；脚本保存与成功回执在同一事务中完成。

## 运行与验证

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
npm --prefix frontend ci
npm --prefix frontend run build
.\.venv\Scripts\python.exe -m uvicorn backend.alexandria.main:create_app --factory --host 127.0.0.1 --port 4201
```

默认数据在当前 checkout 的 `data/`，启动时自动迁移；不要让两个服务共用数据库。升级后需重启后端并刷新网页。沿用本机使用方式，不新增多用户登录系统。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
npm --prefix frontend test
$env:PLAYWRIGHT_PORT = '5184'
npm --prefix frontend run test:e2e -- agent-flow.spec.ts
npm --prefix frontend run build
```

测试使用临时数据库、可控时钟、模拟模型与模拟 B 站服务，不实际上传或调用付费配音。可选的真实模型验证脚本仍只写临时数据，调度器关闭：

```powershell
.\.venv\Scripts\python.exe -m tools.validate_agent --settings-db 'D:\path\to\configured\alexandria.db'
```

该脚本会调用真实模型、可能产生费用，检查状态查询、任务提交、单章和批量直接改稿；不会操作真实项目或上传。

加 `--schedule-only` 可使用模拟账号和已准备视频验证真实模型创建延迟计划、唤醒后追加 10 个分 P、忙时及无内容时跳过。可用 `--compare-project UUID` 只读加载指定项目最近历史，在临时数据库中复现旧上下文问题。不会启动实际上传调度或写原数据库。
